Service ContentReader [DEF-S1]

Read-only bounded access through configured native Store+Local adapters. Naming lookup is unverified; unsupported providers refuse. Writes use the separate content-writer profile. Callbacks are trusted provider code required to honor bounded execution/context.

Wire identity: abstraction.storage/content-reader@1

Multiple services share this namespace. Generated ServiceName (Go) and service_name (C++/Python) validate the request envelope and version before returning its service identity for routing. The selected generated dispatcher validates the method and typed arguments; the selector does not authorize callers or interpret method payloads.

Frames carry version, service, method and typed arguments. Transport owns framing, associated exchanges, deadlines and connections. Unknown version/service/method and malformed arguments are rejected before invoking a handler. One-way WriteFrame success means local submission, not remote acceptance or persistence.

Request-response methods use ExchangeFrame. Replies carry version, service, method, ok and payload; success payload contains typed value (or an empty object for void). Error payload contains nonempty code and message, which may be empty. ServiceError preserves unknown codes. Unexpected handler failures become handler_error without private details; invalid results become invalid_result. Clients validate reply identity and result before exposing it. A malformed frame or transport failure remains a local error; the transport must associate each response with its exchange. C++ dispatchers are pure protocol bindings, not listening servers.

Canonical sha256: plus 64 lowercase hexadecimal digits. Explicit content policy required; same-account identity alone grants no content permission. At most 32 resources globally and 8 per scope; 30 seconds idle expires.

Service ContentWriter [DEF-S1]

Bounded authorized writes through configured native Store+Local+Writable adapters. Uploads idle for 30 seconds expire and are discarded. Committed request records are retained for 10 minutes within one provider lifetime. Provider shutdown discards staged uploads.

Wire identity: abstraction.storage/content-writer@1

The selected generated dispatcher validates the method and typed arguments; the selector does not authorize callers or interpret method payloads.

request is a caller-retained identity of 16..128 characters from A-Z a-z 0-9 _ -, scoped to the receiving account/program. digest is canonical sha256; size is the declared total, 0..limit. Write authorization precedes every lookup and provider effect. The same request with the same digest and size returns its live upload or committed result; different digest or size is conflict. present reports an existing naming match. busy reports another live upload of the same digest. At most 16 uploads globally, 4 per scope and 256 request records.

  • Argument 2: string digest (required, including zero/false/empty)
  • Argument 3: i64 size (required, including zero/false/empty)

data is 1..65536 bytes at offset equal to received. Authority rechecked before bytes are staged. A different offset stages nothing and returns out_of_order with received. Bytes beyond the declared size stage nothing and return too_large. Unknown/expired/aborted/restarted uploads give gap; another scope's upload gives forbidden.

Service ContentChanges [DEF-S1]

Bounded authorized observation of objects a content store gains or loses. The provider journal retains a bounded number of recent changes per lifetime with no per-subscriber queue; a subscriber that falls behind receives gap and rebuilds from List. Service-mediated commits are journaled when they publish. External additions and deletions are journaled when the provider's optional listing capability is polled; changes that cancel out between polls are not reported. removed currently reports only external deletions, because the service has no delete operation. A provider restart starts a new epoch.

Empty cursor starts at the current journal end. Cursors are at most 256 bytes and bind provider epoch and sequence. A cursor from another epoch or older than the retained journal returns gap. max_changes is 1..256; wait_ms is 0..30000 and waits at the current end for an append, then rereads once. Observe authorization is checked on every call and rechecked after a wait; each entry is filtered through the read policy for its digest. A read decision outage returns unavailable without advancing. Bounded waiter exhaustion returns unavailable.

  • Argument 1: string cursor (required, including zero/false/empty)
  • Argument 2: i64 max_changes (required, including zero/false/empty)
  • Argument 3: i64 wait_ms (required, including zero/false/empty)

Empty continuation freezes a new snapshot of the provider's known objects and its change cursor. limit is 1..256. Continuations are at most 256 bytes and name a retained snapshot; an unknown, expired or restarted snapshot returns gap. At most 8 snapshots are retained, each for 30 idle seconds; exhaustion returns unavailable. Observe authorization and per-object read filtering apply as for Observe.

Service Holds [DEF-S1]

Holds are retained until released, expired, or the program is removed under the uninstall policy; released and expired holds read unknown after audit_retention_ms, readable on an inventory page.

Service InventorySource [DEF-S1]

A provider the runtime reads. The source listens on the shared identity-bound transport and serves only its own account. A call whose peer identity could not be obtained fails with the error code caller_unavailable, and one on a transport that bound no identity with identity_required; a bound peer of another account reads forbidden. The runtime accepts a source only under an abstraction.storage/inventory.provide rule for the bound program and the named stores. Sources never talk to applications.

Wire identity: abstraction.storage/inventory-source@1

Handler error codes, declared by inventory_source_error_codes: caller_unavailable, identity_required. Generated bindings name each as a ServiceErrorCode member beside the dispatcher's own codes.

Enumerations [DEF-T5]

An enumeration is a closed vocabulary of wire names, and each one says on its own what a reader does with a member it has never heard of [DEF-A5].
